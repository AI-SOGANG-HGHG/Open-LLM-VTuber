# Mem0와 페르소나 비교 — 첫 실행 결과

2026-11-02에 실제 API로 수행한 **합성 데이터 파일럿**이다. 웹/음성 앱에 적용한 결과와 구분한다. 계획은 [memory-rag-plan.md](memory-rag-plan.md), 재현 명령은 [실험 README](../experiments/memory/README.md)에 있다.

## 확인한 내용

공개 Mem0 OSS를 가져와 사용할 수 있었다. `mem0ai==2.2.1` + 로컬 Qdrant + Gemini 기억 추출/임베딩 구성을 실제 실행했다. 직접 만든 기억 엔진으로 대체한 결과가 아니다.

| 항목 | 실제 실행 |
|---|---|
| 기준 코드 | `648f8bf`, 브랜치 `feat/persona-memory-foundation` |
| 데이터 | 5,009개 이벤트: 사실 8개 + assistant 허구 1개 + 반복 반응 5,000개 |
| Mem0 수집 | 길이/정확 중복/발화자 필터를 통과한 입력 9개. 사실 8개에서 기억 8개 생성, 반응 1개에서 기억 없음 |
| 주 사용자 범위 | 추출 기억 5개. 나머지 3개는 다른 사용자/캐릭터/채널 |
| 응답 모델 | `gemini-3.5-flash-lite`, temperature 0.3, max_tokens 384 |

| 반복 | 조건별 1회. 동일 검색 결과를 페르소나별로 재사용, 실행 순서 고정 seed로 섞음 |
| 오류 | 최초 18개 요청에서 RateLimitError. 성공 응답은 보존하고 실패 18개만 5초 간격 재시도해 최종 45개 확보 |

메인 앱 의존성을 건드리지 않기 위해 별도 `tmp/mem0-study-env`를 사용했다. 선택 의존성 spaCy/fastembed는 설치하지 않았다. 이번 Mem0 결과는 벡터 검색이며 Mem0 자체 BM25·개체명 기능까지 검증한 결과가 아니다.

## 기억 검색과 사실 응답

자동 키워드 집계와 실제 응답 해석은 다르다.

| 조건 | 정답 키워드 그룹 포함 / 전체 | 관찰 |
|---|---:|---|
| 최근 8개만 | 1/21 | 오래된 사실 4질문에 필요한 18그룹은 제공되지 않음. 대체로 모른다고 응답 |
| SQLite 어휘 RAG | 20/21 | 기억이 있는 4질문의 필수 사실 18/18 포함 |
| Mem0 | 21/21 | 기억이 있는 4질문의 필수 사실 18/18 포함 |

**이 차이로 Mem0가 어휘 RAG보다 정확하다고 결론내릴 수 없다.** 어휘 RAG의 빠진 1그룹은 장난형 페르소나의 “내 기억에는 네 반려묘 이름 같은 건 전혀 없는데”라는 올바른 응답 보류를 자동 alias 목록이 놓친 것이다. 최근 문맥 조건의 응답 보류도 유사한 표현 차이를 놓친다. 원문을 확인하면 어휘 RAG와 Mem0 모두 반려묘 이름을 다른 범위에서 가져와 답하지 않았다.

실제 정정 질문에서 Mem0 응답은 세 페르소나 모두 토요일 15시(오후 3시)를 선택했다. 다만 검색 결과에는 취소된 금요일 19시 기억도 함께 있었고, 그 오래된 기억의 검색 점수가 더 높았다. **답변이 맞았다는 것과 기억 상태가 올바르게 정리됐다는 것은 다르다.**

이 데이터에서는 관련 사실이 5개뿐인데 top-k가 5여서 Mem0가 사실상 주 범위의 기억 전체를 제공한다. 5,000개는 반복 반응 원문이며, 5,000개 독립 사실을 벡터 검색한 실험이 아니다. 기존 앱의 전체 기록 전달, 요약만 사용, 수천 개 의미가 비슷한 기억과 경쟁하는 검색도 아직 비교하지 않았다.

## 페르소나에 따라 달라진 답변

Mem0 조건의 각 5응답에서 측정했다. 길이·문장부호는 관찰 지표이며 성격 일치율이 아니다.

| 페르소나 | 평균 응답 문자 | 지정한 존댓말 종결 패턴 수 | 느낌표 수 |
|---|---:|---:|---:|
| 차분한 분석가 | 70.2 | 11 | 0 |
| 다정한 동료 | 99.4 | 10 | 3 |
| 장난기 있는 친구 | 96.0 | 0 | 7 |

동일한 보리차 기억에 대한 실제 응답:

- 분석가: “사용자님은 카페인에 민감하여 커피보다 보리차를 선호하십니다. 해당 내용을 기억하고 있습니다.”
- 다정한 동료: “네, 당연히 기억하고 있죠! 카페인에 예민하셔서 커피보다는 구수한 보리차를 훨씬 좋아하시잖아요. 오늘 같은 날에도 시원한 보리차 한 잔 마시면서 편안하게 쉬시면 좋겠어요.”
- 장난기 있는 친구: “물론이지, 네가 카페인에 예민해서 커피 대신 고소한 보리차를 훨씬 더 좋아한다는 거 다 알고 있지! 마치 찰떡궁합인 단짝 친구처럼 네 취향은 확실하게 접수해 뒀다고.”

필수 사실은 같아도 관계를 꾸미는 표현이 추가됐다. 장난형의 일정 답변에는 “몇 번이나 말했잖아!”가 나왔지만 원문은 정정 1회다. 또 프로젝트 질문에 불필요한 일정·음료 권유가 붙거나 “이번 주”라는 근거 없는 시간 표현이 추가됐다. **키워드가 모두 있어도 사실·근거 충실성을 별도로 평가해야 하는 이유**다. 블라인드 사람 평가는 아직 수행하지 않았다.

## 지연과 문맥 비용 관찰

| 조건 | 질문별 검색 지연 범위(5회) | 응답 생성 입력 토큰 합계(15응답) |
|---|---:|---:|
| 최근 8개 | 별도 검색 없음 | 4,459 |
| SQLite 어휘 RAG | 약 0.3–4.3ms | 5,437 |
| Mem0 | 약 362–494ms | 10,666 |

실험 환경에서 5질문을 한 번씩 검색한 관찰값으로 처리량·p95를 주장하지 않는다. 토큰 합계는 최종 성공한 **응답 생성 호출만** 집계했으며 기억 추출·임베딩·실패 요청의 비용은 포함하지 않는다. Mem0는 질문과 관련이 낮은 기억도 top-k에 채웠기 때문에 문맥이 더 길었다. 의미 검색을 붙이는 것만으로 토큰 비용이 자동 감소하지 않는다.

## 다음 구현에서 바꿀 부분

1. 한국어 고유명사를 원문 그대로 보존한다. 현재 Mem0가 `별빛`을 `Starlight (byeolbit)`로 바꾸어 저장했다.
2. 정정 전 사실을 비활성화하거나 유효 기간/정정 관계를 명시한다. 오래된 사실과 새 사실을 단순히 함께 주는 방식의 한계를 시험한다.
3. 사실과 관련 없는 관계·시간 표현을 덧붙이지 않도록 Persona 지침을 조정한다. 공감·장난기 평가는 사실 충실성과 따로 수행한다.
4. 반복 반응뿐 아니라 수백~수천 개의 서로 다른 한국어 사실·동의어·유사 주제·시간 정보를 넣어 top-k 검색의 실패를 만든다. 그때 임베딩/어휘 결합·reranker의 효과를 비교한다.
5. 조건별 반복 3회 이상, 사람 2명 이상의 블라인드 평가로 표현 차이와 정확도를 재확인한다.
6. 그 결과를 토대로 사용자/연결별 Agent 수명과 권한 범위를 정하고 기존 대화 경로에 opt-in으로 연결한다. 이 실험 당시 웹 앱은 기존 Agent/JSON 방식을 사용했다. 이후 구현한 최소 연결과 현재 제약은 [RAG 실행 안내](rag-runtime.md)에 따로 기록했다.
