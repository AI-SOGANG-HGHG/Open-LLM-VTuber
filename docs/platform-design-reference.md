# Persona Studio 디자인 참고와 적용

2026-11-11. `feat/platform-foundation` 로컬 시연 화면 개편. 공개 서비스 페이지와 공식 제작·기억 안내를 참고했으며 로그인 후의 비공개 화면 전체를 조사했다는 뜻은 아니다. 다른 서비스의 캐릭터 이미지·로고·문구는 복사하지 않았다.

어두운 배경·코랄 강조색·큰 캐릭터 이미지·영문 타이포 조합은 위 구조를 바탕으로 이 프로젝트에 맞게 선택한 자체 디자인이다. 특정 서비스의 화면을 그대로 재현한 것이 아니다.

## 기존 버전에서 달라진 점

- 베이지·초록 대시보드에서 캐릭터 중심의 어두운 스튜디오로 전체 화면 재구성.
- Open-LLM-VTuber의 `model_dict.json`에 등록된 기본 모델 `mao_pro`를 Mao 카드·프리셋·생성/편집 외형 선택지에 추가.
- Mao 썸네일은 기존 로컬 모델을 실제 렌더링해 생성. 출처와 Live2D 고지는 [리소스 안내](../web_tool/platform/assets/README.md)에 기록.
- 캐릭터별 즐겨찾기, 전체/즐겨찾기/Live2D 필터, 검색, 프리셋 생성, 첫 인사 편집, 빠른 대화, 실제 Live2D 외형 미리보기 제공.
- v1 브라우저 저장 데이터의 캐릭터·메모·대화를 유지하고 Mao를 한 번 추가. 이후 사용자가 삭제한 Mao를 다시 강제 추가하지 않음.
- 개편 초기에는 실제 대화와 분리된 샘플 화면이었다. 이후 스튜디오 내부의 실제 모델·음성·Live2D 연결을 추가했다. 실제 계정 인증·사용자 권한·자동 기억/RAG·방송·게임은 남아 있다.

## 검증

로컬 Chrome에서 43개 흐름·회귀 확인을 수행했다. Mao/서강이 실제 Cubism 렌더링, 닫기 후 리소스 해제, 즐겨찾기·검색·필터, 외형 선택과 저장, 첫 인사, 샘플 대화, 메모 격리·복원, 복제·삭제, v1 이전과 삭제 유지가 포함된다. 목록·탐색·설정·대화·연결·기록을 360·390·768·1440px에서 확인했다. 실제 대화 API와 방송·게임은 호출하지 않았다.

## Chrome 오류 제보 후 추가 확인

사용자는 플랫폼을 조작하지 않은 상태에서 `chrome.exe`의 `0x80000003` 오류창을 제보했다. 확인한 서버는 정상 응답했고 검증용 Chrome에서는 같은 프로세스 충돌을 재현하지 못했다. 자동 브라우저 시작 환경을 가능 원인으로 조사했지만 근본 원인은 확정하지 못했다. 사용자의 일반 Chrome 창을 종료하거나 설정·프로필을 변경하지 않고, 별도 임시 검증 브라우저만 종료했다. 정상 사용자 실행 환경에서 데모를 다시 열어 페이지와 화면 리소스 요청 성공을 확인했다.

추가로 Live2D의 `webglcontextlost`를 처리해 이미지를 복구하도록 보강하고, 미리보기 해상도를 최대 1.5배로 제한했다. 실제 WebGL 컨텍스트 소실 → 이미지 전환 → Live2D 다시 열기 → 샘플 대화 유지 검사는 통과했다. 이 검사는 Windows Chrome 프로세스 충돌의 원인 규명이나 완전 해결을 의미하지 않는다.

## 스튜디오 내부 실제 대화 연결

캐릭터 카드·빠른 연결·연결 허브가 모두 스튜디오 내부 대화실로 이어진다. 기존 서강이의 대화·ASR·TTS·재생 큐·중단·복원 기능을 임베드하고, 선택한 캐릭터를 검증된 브리지로 전달한다. 새 탭으로 기존 앱을 여는 방식은 기본 동선에서 제거했다.

서버의 `apply-studio-persona` 명령은 이름·성격·말투와 직접 등록한 메모를 현재 연결의 Agent에 적용한다. 엔진과 자격 증명은 서버 설정을 사용하며, 캐릭터 YAML과 다른 연결은 변경하지 않는다. 기록 범위는 브라우저 workspace UUID와 캐릭터 ID로 구분한다. 이는 로그인·사용자 권한을 대신하지 않는다.

실제 API 검증에서 선택한 이름과 등록한 합성 메모를 모델 응답이 반영했고, 음성 재생에 따라 Mao 입이 움직였다. 서강이의 실제 응답·음성·입 움직임·손 인사, 새로고침 복원, 캐릭터별 기록 분리도 확인했다. 백엔드 회귀 39개가 통과했다. MP3를 FFmpeg로 명시적으로 디코딩해 추가 ffprobe 없이 WAV와 립싱크 볼륨을 만드는 회귀 검사도 포함된다.

기존 임시 환경의 Gemini 키가 재시작 후 없어 사용자가 로컬 마스킹 입력창에서 다시 연결했다. 키를 채팅이나 파일로 저장하지 않고 서버 프로세스 환경에만 전달했다. API 없는 샘플 대화는 별도 탭에 유지했다.

## Mao 선택 외형 수정

공통 앱의 준비 전 이미지 갱신이 서강이 리소스를 고정 사용해 Mao 로딩 중에도 서강이가 나타날 수 있었다. 해당 처리를 서강이 외형으로 제한했다. 스튜디오는 `/web-tool/platform/runtime/`의 중립 실행 화면을 사용하고, 설정을 받기 전 특정 캐릭터를 표시하지 않는다. 실제 동작 코드는 기존 대화 엔진을 공유한다.

부모의 선택, 실행 화면이 받은 설정, 서버가 적용한 캐릭터 ID·외형·이름을 대조한다. 모델 요청을 의도적으로 지연·실패시킨 브라우저 검사에서 Mao 이미지 유지와 정상 로드·캐릭터 전환을 확인했다. 심볼 캐릭터가 서강이로 바뀌지 않는 것도 확인했다. 이 검사는 대화 모델 API를 호출하지 않았다.

## 대화 무대와 배경 복원

스튜디오 공통 스타일이 기존 무대 배경을 덮고 있던 부분을 수정했다. 원본 프론트의 `BgUrlProvider`에서 기본값으로 사용하는 `/bg/ceiling-window-room-night.jpeg`를 Mao의 기본 배경으로 복원했다. 서강이는 기존 캠퍼스 배경을 유지한다.

캐릭터 관리에서 대화를 시작하면 같은 창에서 관리 메뉴를 접고 무대·캐릭터·대화를 넓게 표시한다. 스튜디오로 돌아가는 링크와 연결을 유지하며 관리 메뉴를 표시하는 전환 버튼을 제공한다. 배경 선택은 캐릭터별로 저장하며 기존 원본 앱 설정을 변경하지 않는다. 실제 이미지 로드, 보기 전환 중 실행 인스턴스 유지, 배경 변경·복원·캐릭터별 분리, 모바일 입력창의 뷰포트 포함을 브라우저에서 확인했다.
