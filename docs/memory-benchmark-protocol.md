## 정보 누출과 평가 범위

- 기억 수집에는 양쪽의 과거 발화를 포함한다. `single-session-assistant` 문제를 사용자 발화만으로 평가하지 않는다.
- `answer`, `answer_session_ids`, `has_answer`, MemOps `operations`/정답 상태/근거 라벨은 검색·추출·응답 생성 입력에서 제외한다. 질문은 검색과 응답 생성 시에만 제공한다.
- `answer_*`처럼 정답 여부를 암시할 수 있는 원본 세션 ID 대신 모델에는 `s000-t000-p000` 형태의 ID를 보여 준다. 원본 ID 매핑은 평가 단계에서만 쓴다.
- 한국어는 같은 인물의 **질문 시각까지** 발화만 제공한다. 원문에 없는 근거 ID, 다른 인물의 근거, 미래 근거가 정답 라벨에 들어 있으면 실패 처리한다.
- `oracle`은 정답 근거를 사용한 진단용 상한선으로 명시하며 실제 검색 방식과 합산하지 않는다. 이번 주요 실행에는 oracle을 사용하지 않았다.
- 모델 입력의 근거 예산은 JSON 직렬화 후 24,000문자다. 모델 토큰 한도와 같지 않다. 2,400문자 chunk와 150문자 overlap을 사용한다.
- 고정 seed `20261102`와 질문 ID 해시로 표본을 선택한다. 점수를 본 뒤 잘 맞는 문제로 바꾸지 않는다. 응답 보류는 별도 층으로 분리하여 총 7유형이다.

## 측정하는 수치

검색은 답이 있는 470문항에서 계산하고 응답 보류 30문항은 분모에서 제외한다.

1. 정답 근거 **세션** 회수 비율과 모든 근거 세션 발견 여부.
2. `has_answer`로 표시된 **발화**에서 나온 chunk를 회수한 비율과 모든 근거 발화 hit 여부.

한 세션의 다른 문장을 찾았다고 근거 발화를 찾은 것은 아니다. 발화 hit도 그 긴 발화의 일부 chunk만 포함할 수 있으므로 정답 자체가 문맥에 충분히 들어 있다는 보장은 아니다. 정답 정확도와 구분해서 보고한다. 이 chunk·문자 예산 설정의 검색 수치는 공식 리더보드 점수와 직접 비교하지 않는다.

응답은 `question_id`, `hypothesis` JSONL로 내보내 공식 채점기에 전달할 수 있다. 답변 길이 제한·프롬프트 형식·응답 모델·채점 모델·표본 수를 함께 기록한다.

## 채점 모델과 교정

공식 기본 judge는 `gpt-4o-2024-08-06`이다. 현재 로컬에는 Gemini 키만 있어 최초 채점은 응답 모델 `gemini-3.5-flash-lite`를 사용한 **보조 점수**로 저장했다. 이를 공식 모델 채점 결과라고 표현하지 않는다.

같은 모델의 한국어 판정에 부적절한 사례가 발견되어, 응답과 별개인 `gemini-3.5-flash` 심사 모델을 위한 검사·재채점 도구도 추가했다.

- 공식 유형별 명백한 정답/오답과 한국어 응답 보류를 포함한 대조 문항 16개로 검사한다.
- 모두 통과한 경우에만 이미 고정된 응답을 재채점한다. 답변 생성·기억 추출은 반복하지 않는다.
- 공식 LongMemEval judge 프롬프트 함수는 AST 비교로 원본과 일치함을 검사한다. 심사 모델·yes/no 파싱·출력 한도가 다르므로 여전히 보조 평가다.
- 한국어와 MemOps는 별도의 참조 정답 기반 보조 판정이다. heard 저자의 토큰 포함 baseline, MemOps 공식 다중 지표 judge를 재현한 점수와 구분한다.
- 대조 문항 통과는 실제 어려운 문항에 대한 신뢰성을 보장하지 않는다. 보조 judge 사이에 판정이 다른 응답과 임의 표본은 사람이 검토해야 한다.

MemOps의 언어적 “잊어 달라” 요청을 이해하고 답하는 것과 저장소에서 그 정보가 실제 삭제되는 것은 별개다. 이번 인접 QA 결과로 저장소의 자연어 삭제 처리가 완료됐다고 주장하지 않는다.

## Mem0 처리와 실행량

공개 `mem0ai==2.2.1`을 사용한다. 질문별로 격리된 소유 ID에 전체 과거 대화를 시간·화자 표시와 함께 최대 32,000문자씩 순서대로 수집한다. 모델에 보이는 source block에는 정답 라벨과 질문을 넣지 않는다. 추출 지침은 원래 이름·날짜·화자·정정·확정/잠정 구분을 보존하도록 지정했다. 추출 출력 한도는 4,096토큰이다.

이 방식은 Mem0 기본 설정 그대로의 공식 성능 측정이 아니라, 이 프로젝트의 전처리·추출 지침을 사용하는 실험 구성이다. Mem0의 추출 기억은 원문 발화와 정확하게 대응하지 않으므로, 원문 검색과 같은 근거 발화 hit 점수를 억지로 계산하지 않는다. 최종 응답 판정과 실제 입력/추출 결과를 별도로 남긴다.

500문항에는 총 23,867세션·246,750발화가 있다. 현재 Gemini 무료 임베딩 API에서 분당 30,000토큰 제한을 실제 관찰했다. API 오류는 성공/빈 기억으로 바꾸지 않으며 완료한 블록·응답·판정은 보존하고 재개한다. 제한에 따른 대기 시간과 Mem0 내부 호출 때문에 전체 실행량은 단순한 `500 × 응답 1회`가 아니다.

실행 순서는 전체 검색 → 고정 표본의 응답 → Mem0 전체 이력 처리 점검 → 심사 모델 검증 → 더 큰 실행으로 확장한다. 문항 일부의 점수를 500문항 전체 점수로 외삽하지 않는다.

공식 데이터에서의 페르소나 비교는 우선 중립 응답의 기준을 잡은 뒤 동일한 검색 근거를 고정하여 수행한다. 앞선 합성 페르소나 파일럿 결과를 공식 데이터의 성격 평가로 재사용하지 않는다.
