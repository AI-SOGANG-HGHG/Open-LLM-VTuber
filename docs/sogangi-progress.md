# 서강이 시제품 작업 기록

## 2026-11-03 화남·놀람 표정 확장

기존 세 모델과 PSD를 보존하고 공식 PDF의 화남 눈/입과 발견 입을 추출해 별도 29개 레이어 PSD를 만들었다. 기존 24개 레이어의 픽셀·좌표·가시성과 중립 합성을 그대로 확인했다. 눈 확대와 화난 열린 입의 비율 조절은 프로젝트의 키폼 변형이다. 별도 실제 표정 모델은 29 Drawable·29 Core 파라미터 중 7개를 연결한다.

표정 가시성과 깜빡임/입 벌림의 불투명도를 곱해 서로 덮어쓰지 않도록 했다. 추가 파츠 때문에 생긴 미세한 UV 샘플 차이는 기존 텍스처 배치 유지로 해결했고 중립 런타임 픽셀도 이전 모델과 정확히 같아졌다. 중립·기쁨·화남·놀람을 지원하며 원화 없는 슬픔·비웃음·두려움은 중립으로 처리한다. SVG는 기존 중립/기쁨으로 복귀한다.

문장 재생 순서·음소거·중단·모드 전환·동작 줄이기에서 실제 Core 표정을 확인했다. 표정 exp3 파일 4개도 실제 Core에서 재생했으며 입 벌림을 덮지 않는다. 기본 앱은 같은 의미 값을 직접 Core에 전달한다. 이번 변경에는 모델/TTS 서비스 API를 호출하지 않았다. [파일·재현·검증 범위](../live2d-models/sogangi-expressions/README.md)를 참고한다. 아래 기록은 각 시점의 상태다.

최종 Ruff·Python 32개·브라우저 59개와 SVG 기준 화면 6종을 통과했다. 화남/놀람을 재생 음성·고개·팔과 함께 검사한 PC/모바일 좌우 8개 캡처 모두 잘림이 없었다. 표정 cmo3는 공식 Editor에서 재열었다. 태그와 재생의 연결 검증이며 모델이 감정을 적절히 선택하는지는 별도 페르소나 평가 범위다.

## 2026-11-03 오른팔 인사 연결

앞선 두 모델을 보존하고 별도 `sogangi-greeting` cmo3/moc3를 만들었다. 기존 화면 오른팔과 설계 피벗을 사용해 `ParamArmRWave` 0–1에 5개 키폼과 최대 −32° 회전을 연결했다. 24개 Drawable·28개 Core 파라미터 중 6개를 제어한다. 기존 상체 호흡 전에 팔 변형을 조합하며 새 원화를 그리거나 팔꿈치/손가락을 나눈 결과는 아니다.

눈·입·고개·호흡의 조합과 중립 픽셀을 보존했다. 팔/호흡의 중간 자세 12개에서 큰 연결 성분 수가 유지되는 것을 검사하고 어깨를 시각 검토했다. 완전한 해부학·가림 검수와 구분한다. 원본 cmo3는 실제 Editor에서 재열었다. 대화 화면의 손 흔들기는 1.6초 후 복귀하며 API를 호출하지 않는다. 중복 클릭은 쌓지 않고 중단·새 대화·모드 전환·동작 줄이기에서 취소한다.

파일·출처·재현·검증 범위는 [인사 모델 안내](../live2d-models/sogangi-greeting/README.md)를 따른다. 이번 변경에는 추가 LLM/TTS API 요청을 쓰지 않았다. 아래 기록은 각 시점의 상태다.

최종 Ruff·Python 32개·브라우저 55개·SVG 기준 화면 6종을 통과했다. 음소거의 팔 취소도 추가 확인했다. PC/모바일 좌우 끝 고개와 팔 인사를 함께 캡처한 4개 화면에서 캔버스 가장자리의 불투명 픽셀은 모두 0이었다.

## 2026-11-03 고개·호흡 확장 모델

기존 눈·입 기준 파일을 보존하고 별도 `sogangi-motion` cmo3/moc3를 생성해 대화 화면의 기본 모델로 연결했다. 24개 Drawable·27개 표준 파라미터 중 5개를 연결했다. 고개/모자 파츠에 최대 ±3°의 작은 정면 기울기, 다리를 제외한 상체에 작은 호흡을 적용한다. 실제 디포머 계층이나 입체 회전을 만든 것은 아니다.

변환 도구가 파라미터마다 기존 키폼을 지우는 문제를 프로젝트 전용 어댑터의 다차원 키폼 조합으로 해결했다. 원본 기본 폼을 먼저 복사해 열린 입이 중복 축소되던 부분도 수정했다. 참고 checkout과 Editor 프로그램 파일은 수정하지 않았다. 중립 픽셀은 이전 모델과 정확히 같으며 눈·입·기울기·호흡을 함께 조작하고 초기화하는 Core 검사를 통과했다.

대화 화면은 마우스 방향을 부드럽게 따라 기울고 4.8초 호흡을 반복한다. 앱/OS 동작 줄이기에서는 고개·호흡이 0으로 돌아가며 음성 립싱크는 유지한다. 파일·출처·재현과 검증 범위는 [확장 모델 안내](../live2d-models/sogangi-motion/README.md)에 있다. 이번 모델 변경에는 추가 LLM/TTS API 요청을 사용하지 않았다. 아래 기록은 각 시점의 상태다.

최종 소스의 모델을 Editor에서 재열고 Python 32개·브라우저 52개·SVG 기준 화면 6종을 통과했다. 추가 좌우 끝 자세 검사에서 날개 끝 잘림을 발견해 6% 여백과 발 기준 배치를 보완했다. 수정 후 Live2D 대화 9개와 잘림 회귀를 재확인했고 PC/모바일 좌우 4개 캡처 모두 캔버스 가장자리의 불투명 픽셀은 0이었다.

## 2026-11-03 Live2D 기본 표시로 전환

후속 요청에 따라 Live2D를 기본 렌더러로 전환했다. 이전에 저장한 SVG 선택은 유지하며 설정 또는 `?avatar=live2d`로 바꿀 수 있다. URL의 명시적 선택도 브라우저에 저장해 일반 주소 재접속에 적용한다. SVG는 선택형 모션과 실패 복구용으로 유지한다. 아래 연결 기록은 기본값 전환 전의 상태다.

전환 후 Python 32개·브라우저 50개·화면 크기 6종 검사를 통과했다. 새 기본값과 SVG→URL 선택→일반 주소의 저장 유지까지 실제 Core로 확인했다. 이 검증에서는 모델 API를 추가 호출하지 않았다.

## 2026-11-03 Live2D 대화·음성 연결

설정 또는 `?avatar=live2d`로 실제 최소 MOC3를 대화 화면에서 선택하도록 연결했다. 기본 SVG는 고개·시선·인사를 유지하며, 최소 Live2D는 눈·입만 제어하고 미구현 인사 버튼을 비활성화한다. 로드/컨텍스트 오류 시 SVG 복귀와 재시도를 제공한다. 렌더러 전환은 대화 요청·음성 큐·기록을 재시작하지 않는다.

실제 Core와 브라우저 오디오 시계를 사용하는 회귀 검사 8개에서 입의 픽셀 변화/정확한 닫힘 복귀, 문장별 표정, 중단·음소거, 지연 로드, 재생 중 모드 전환, 오류 복구와 새로고침을 확인했다. 실제 Gemini/TTS 요청 한 번도 통과했다. 첫 문장 0.7초·첫 음성 1.9초, 실제 Core 입 값 최대 1/종료 0과 기록·초안·Live2D 복원을 관찰했다. 이 시간은 한 번의 표본이며 물리 스피커를 청취한 검증은 아니다.

최소 모델의 원본·해시와 [검증 범위](../live2d-models/sogangi-minimum/verification.json)를 유지했다. 고개/몸 디포머·호흡·팔·확장 표정/모션 파일과 장기 사용 검수는 다음 제작 범위다. 아래 기록은 각 시점의 상태다.

연결 후 Ruff·Python 32개·브라우저 50개와 여섯 화면 크기의 API 없는 전체 검사를 통과했다. 실제 API 검사는 위 인사 한 번이며 전체 검사에서 추가 호출하지 않았다.

## 2026-11-03 첫 실제 Cubism 눈·입 모델

보이는 설치창으로 다시 실행한 뒤 Cubism Editor 5.1.03의 설치와 실행을 확인했다. 실제 PSD 가져오기, GUI 자동 메시 생성과 로컬 cmo3 저장, 최종 최소 cmo3의 Editor 재열기를 수행했다. 사용자에게 보인 실행 환경은 평가판 42일 모드였다. 아래의 UAC 취소 기록은 그보다 앞선 시도다.

공개 변환 도구에 명시적 눈/입 바인딩과 2048 아틀라스 여백 패치를 적용해 진짜 MOC3를 만들었다. 24 Drawable, 27개 표준 파라미터 중 눈 2개·입 1개만 연결했다. 첫 아틀라스의 가는 경계선을 실제 화면에서 발견해 파츠 사이 4픽셀 여백으로 해결했고, 원본 크기를 유지했다. Windows Java 출력의 한글 경로 손상도 UTF-8과 경로 포함 관계 검사로 수정했다.

모델·소스·해시·관찰 검증은 `live2d-models/sogangi-minimum/`에, 재현 빌더는 `tools/build_sogangi_minimum.mjs`, 원본 MIT 고지와 패치는 `tools/licenses/`와 `tools/patches/`에 있다. SDK/Editor 바이너리는 프로젝트 임시 폴더에만 있으며 모델 폴더에 포함하지 않았다.

실제 웹 Core에서 눈/입 조작이 픽셀을 바꾸고, 기본값/초기화 복귀 시 중립 픽셀이 정확히 돌아오는 것을 확인했다. 새 서강이 선택 버튼·모바일·기울기 미연결 표기도 검사했다. 전체 Python 32개·브라우저 42개·여섯 화면 크기를 통과했다. 이 단계는 기본 ArtMesh 기반의 최소 얼굴 리깅이다. 고개·몸·팔·표정, 대화 화면 교체와 실제 오디오→Cubism 입 연결은 아직 남았다.

## 2026-11-03 실제 Editor 가져오기 준비

기존 24개 파츠를 픽셀·좌표 그대로 보존하면서 투명 여백을 줄이고 9개 그룹으로 정리한 별도 Cubism 가져오기 PSD를 만들었다. PSD 재열기와 다른 TypeScript/ag-psd 판독기에서 파츠 픽셀·좌표·그룹 경로를 확인했다. 눈·입 3개 파라미터의 명시적 끝값/기본 표시/피벗 표와, 원본 크기의 24개 파츠를 2048 아틀라스 한 장에 배치하는 검토안도 제공한다. 실제 리깅 적용이나 UV 내보내기는 아니다.

공개 자동 도구의 고정 의존성을 설치했고 타입 검사는 통과했다. 제공 테스트는 6개 중 3개 통과, 원본 fixture 누락/변환 오류 3개 실패였다. 우리 PSD는 직접 읽어 확인했으나 그룹 정리 후에도 자동 눈·입 추론은 실패했으므로 자동 연결을 채택하지 않았다.

공식 Cubism 5.1.03 Windows 설치 파일은 다운로드·해시·Live2D Inc. 전자서명 검증을 완료했다. 설치는 Windows UAC 확인이 완료되지 않아 취소됐고, Editor는 아직 설치하지 못했다. `tools/setup_cubism_editor.ps1`에 사전 확인과 사용자가 처리하는 설치/실행 경로를 마련했다. 실제 PSD 가져오기·cmo3 저장·moc3 내보내기는 남아 있다. [실행 순서](sogangi-rigging-integration.md)를 따른다.

변경 후 API 없는 프로젝트 검사 Python 32개·브라우저 41개와 여섯 화면 크기를 통과했다. 설치 사전 확인과 PowerShell 구문 검사도 통과했다. 키·기존 대화·main 등록은 변경하지 않았다.

## 2026-11-03 원화 겹침·표정 전환 후속

원화 동작 비교 화면과 7개 고정 자세의 원본/후보 SVG·PNG를 만들었다. 어깨 캡 2개를 추가한 별도 26개 레이어 PSD도 생성·재열기 검사했다. 정면 Chrome 픽셀은 동일했고 PSD 합성은 151픽셀에서 최대 1/255 차이였다. 7개 자세 모두 후보를 넣어도 보이는 결과가 같아 현재 앱에는 채택하지 않았다. 기존 원화와 24개 기본 PSD는 유지했다. 자세별 측정과 미채택 이유는 [원화 인계 자료](sogangi-art-handoff.md)에 남겼다.

대화 앱의 눈·입 모양은 작은 입력 차이에서 즉시 교체하던 방식을 연속 전환으로 바꿨다. 실제 렌더 픽셀로 기존 임계값 부근의 갑작스러운 변화가 없어졌는지 검사했다. 이는 SVG 시제품 개선이며 Live2D 메시나 중간 원화 납품은 아니다.

전체 API 없는 검사에서 Python 32개, 브라우저 40개(대화 19·제품 14·Cubism 4·원화/전환 3), 여섯 화면 크기를 통과했다. 공개 autoLive2d 도구도 별도 참고 폴더에서 소스·라이선스를 검토했다. 실제 내보내기에는 로컬 Cubism Editor 5.1이 필요하며 확인한 기본 경로에는 없다. 설치 스크립트·MCP 등록·실제 모델 출력은 실행하지 않았다.

## 2026-11-03 표정·실제 모델 검수 후속

답변 태그를 실제 재생 문장의 SVG 표정에 연결했다. 음소거·중단·새 대화의 표정 복귀를 검사했고, 실제 인사 요청에서도 기쁨 표정·음성·입 움직임과 기록 복원을 확인했다.

준비 PSD와 해시가 일치하는 리깅 좌표도를 만들었다. 실제 레이어 24개 경계는 측정값이며 피벗 9개·보완 영역 6개·파라미터 연결 10개는 제작자 검토용 제안이다. 화면 오른팔 인사에 맞춰 ParamArmRWave로 좌우 명세를 정리했다.

별도 검수실에서 기존 Mao의 실제 Cubism MOC3를 표시하고 입·눈·기울기와 표정/모션 검수 경로를 마련했다. 같은 모델을 다시 읽어도 텍스처가 유지되고 오류 입력이 이전 모델을 지우지 않는지 확인했다. 외부 CDN과 대화 API는 사용하지 않는다. 서강이의 새 원화 보완·cmo3·moc3 제작이나 메인 SVG 앱의 Cubism 교체는 아직 하지 않았다.

현재 Python 검사 32개, 브라우저 검사 37개와 여섯 화면 크기를 통과했다. [원화·리깅 연결 안내](sogangi-rigging-integration.md)에 파일 검사·원화 보완·실제 모델 등록 순서를 기록했다.

## 시각 품질 개선

사용자가 기존 Live2D 화면보다 퀄리티가 낮다고 지적한 뒤 화면을 다시 구성했다.

- 큰 소개 문구를 제거하고 데스크톱 캐릭터를 확대했다.
- 세밀한 생성 배경을 단순한 색·형태의 `campus-lounge.svg`로 교체했다. 실제 캠퍼스 건물이 아닌 가상의 라운지다. 이전 생성 배경은 참고로 보관했다.
- 발밑 그림자와 발을 기준으로 한 작은 호흡을 적용하고 과한 전체 몸 흔들림을 줄였다.
- 말풍선을 얼굴/후드 위에서 벗어나도록 옮기고 작은 화면의 잘림도 수정했다.
- 모바일에서는 메시지 영역만 스크롤하고 입력창이 첫 화면에 남도록 구성했다. 가로 화면도 별도로 조정했다.
- 제작 설계에 기존 Mao와 비교할 원화·접지·눈·입·후드·팔·접근성 검수 기준을 추가했다.

## 실제 확인 결과

- 백엔드 회귀 검사 **17개 통과**. 외부 API 호출 없이 연결별 기억, 음성 완료·중단, 실패 정책, 로그 마스킹, 기록 목록, 자원 정리를 확인했다.
- 실제 Chrome의 화면/기능 회귀 검사 **16개 통과**. 대화 WebSocket만 fixture로 바꾸므로 이 검사는 LLM을 호출하지 않는다.
- 1440×900, 1920×1080, 768×1024, 390×844, 360×640, 844×390의 여섯 화면 크기를 캡처했다. 가로 넘침, 모바일/가로 화면 입력창 위치와 말풍선 잘림을 검사했다.
- 개선 후 실제 Gemini 소개 요청 **한 번**: 첫 문장 **1.5초**, 첫 음성 **2.0초**. 이름 힌트 없이 서강이 정체성을 답했고, 실제 브라우저 음성 `playing`/`ended`, 문장 우선 표시, 단일 합성 완료, 요청 ID, 입 움직임과 종료 시 닫힘을 확인했다. 이 한 번의 결과로 장기 지연이나 페르소나 일관성을 보장하지 않는다.
- 가상 마이크의 한국어 음원을 실제 녹음→16kHz mono PCM WAV→ASR로 통과시켰다. HTTP 200과 한국어 전사, 녹음 종료 상태를 확인했다. 별도 회귀 검사에서 연결 종료 후 실제 트랙이 `ended`가 되는지도 확인했다.

이전 실측에서는 첫 음성 18.5초와 37.9초도 관찰됐다. 단독 API·모델·프로토콜 비교도 지연 변동이 커서 모델이나 API 경로를 임의 변경하지 않았다. 이번 UI 개선이 모든 API 지연을 해결했다고 설명하지 않는다.

## Live2D 제작 준비와 남은 범위

[Live2D 제작 설계](sogangi-live2d-plan.md), 설계 화면 `web_tool/sogangi/live2d-plan.html`, 기계 판독 명세와 파츠 ZIP을 제공한다. 레이어 그룹·파라미터·동작 목록과 수동 눈/입/기울기 미리보기를 확인할 수 있다.

공식 AI 원본, 레이어 PSD, cmo3, moc3는 아직 없다. 숨은 부분 보완, 입의 중간 원화, 메시 변형, 얼굴 각도와 어깨 연결, Cubism 실행 묶음 제작·연동은 후속 제작이다. 현재 SVG 동작을 완성된 Live2D로 기록하지 않는다.

실제 사람의 마이크·스피커 청취, 다양한 기기의 가상 키보드, 사용자 인증과 디스크 기록 권한 분리는 미검증/미구현이다. 같은 캐릭터의 디스크 기록은 공유 폴더를 사용한다.

캡처와 합성 시험 결과는 Git 제외 폴더 `tmp/sogangi-browser/redesign/`, 가상 마이크 결과는 `tmp/sogangi-browser/microphone-result.json`에 있다. API 키와 개인 대화는 공유 문서에 넣지 않았다. main 병합·커밋·push는 하지 않았다.
