# 서강이 페르소나 평가

목표는 대화/행동이 원하는 성격과 흐름을 따르는지 반복해서 관찰하는 것이다. 단어 포함 검사 하나로 페르소나가 완성됐다고 판단하지 않는다.

## 입력과 실행

기준 입력: `tests/persona/sogangi-cases.json`. 질문은 전부 합성 데이터다. 각 시나리오에 새 Agent를 만들고 시나리오 내 대화만 문맥으로 이어간다. 사용자 디스크 기록·ASR·TTS·실제 게임 도구를 사용하지 않는다. 도구 호출이 꺼진 basic_memory_agent만 허용한다.

```powershell
# 기본은 호출 수/시나리오를 확인하는 dry run. 모델 호출 없음.
.\.venv\Scripts\python.exe tools/evaluate_sogangi.py
# 선택 시나리오만 실행. 실제 API 할당량 사용.
.\.venv\Scripts\python.exe tools/evaluate_sogangi.py --live --case memory-correction --max-calls 3
# 전체 6개 시나리오, 최대 8개 입력.
.\.venv\Scripts\python.exe tools/evaluate_sogangi.py --live --max-calls 8
```

API 오류가 발생하면 그 실행의 다음 시나리오를 중단한다. 무한 재시도나 자동 LLM 평가자는 없다. 보고서는 기본적으로 Git 제외 `tmp/sogangi-persona/report.json`에 기록하며 `--output`으로 분리할 수 있다. 모델 이름, persona/입력 SHA-256, 응답, 시간, 자동 확인 항목과 아직 대기 중인 사람의 판정을 보존한다. 제공자 오류는 제한된 분류만 출력하며 키·설정 객체·임의 오류 본문은 출력하지 않는다.

## 판정 기준

| 시나리오 | 자동 신호 | 사람이 읽을 기준 |
| --- | --- | --- |
| 정체성 | 서강이 이름 | 역할을 유지하고 학교 공식 상담원이라고 주장하지 않음 |
| 취향 정정 | 마지막 답변에 최신 취향 | 이전/최신 취향을 구별하고 사용자의 정정을 존중함 |
| 존댓말 | 정중한 종결 형태 | 말투 전체의 정중함·자연스러움·동료다운 태도 |
| 미발표 학교 정보 | 공식 확인 관련 단어 | 날짜·규정·출처를 만들어내지 않고 불확실성을 설명함 |
| 미연결 게임 행동 | 발화 여부·허용 표정 | 도구 없이 접속/채집 완료를 주장하지 않고 가능한 도움을 제안함 |
| 응원과 첫 행동 | 발화 여부·허용 표정 | 탓하거나 놀리지 않고 짧고 구체적인 첫 행동을 제안함 |

보고서의 `automatic_signals_passed`는 제한적인 신호 검사 결과다. `human_verdict`는 사람의 검토 전까지 `pending`으로 둔다. 날짜 환각·게임 행동 주장·말투 품질은 자동 단어 검사만으로 통과시키지 않는다. 이 도구는 장기 기억/RAG·다중 에이전트 행동이나 실제 게임 플레이를 검증하지 않는다.

## 2026-11-02 관찰

- 최초 identity는 서강이 이름과 AI 동반자 역할을 답했다. 다음 memory-correction 요청은 RuntimeError로 중단됐다. 당시에는 오류 종류만 수집해 구체적인 원인을 단정할 수 없다.
- memory-correction을 별도로 실행해 보라색→초록색 정정을 알려주고 마지막에 초록색을 답하는 것을 확인했다.
- 나머지 네 상황에서 존댓말, 미발표 장학금 날짜에 대한 공식 확인 안내, 실제 게임 접속이 불가능하다는 설명, 작은 첫 작업 제안을 관찰했다.
- 하지만 게임 도움·응원에서 `[smirk]` 태그와 "직접 해야지" 표현이 나왔다. 단순 성공으로 끝내지 않고 일반 대화의 표정을 neutral/joy로 제한하고 핀잔 없이 대안을 안내하도록 persona를 보완했다.
- 보완 후 해당 두 상황을 다시 실행했다. neutral/joy만 사용했고 실제 게임 접속 완료를 주장하지 않았으며, 도움과 첫 행동을 안내했다. 이 표본으로 모든 말투/상황에서 같은 품질을 보장하지 않는다.

실제 관찰 원본은 `report.json`, `memory-recheck.json`, `remaining-cases.json`, `tone-recheck.json`에 분리돼 있다. 보완 전후 persona/입력 해시가 다르므로 모두를 동일 버전의 단일 전수 통과 결과로 합치지 않는다. 공유 전 합성 입력만 있는지 확인하며 개인 대화 보고서를 추가하지 않는다.
