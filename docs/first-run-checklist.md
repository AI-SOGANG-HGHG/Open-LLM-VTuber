# 다른 PC에서 첫 실행·회의 준비 체크리스트

목표는 기존 기능의 동작과 한계를 확인해 공통 플랫폼 설계의 근거를 만드는 것이다. 이 문서는 검사 절차이며 앱 기능을 이미 검증했다는 결과가 아니다.

## 1. 실행 전 준비

다른 PC에서는 팀 저장소와 프론트 서브모듈을 함께 내려받는다.

```shell
git clone --recurse-submodules https://github.com/AI-SOGANG-HGHG/Open-LLM-VTuber.git
cd Open-LLM-VTuber
```

이미 일반 clone으로 내려받았다면 저장소 안에서 다음 명령을 실행한다.

```shell
git pull --ff-only
git submodule update --init --recursive
```

설치는 [한국어 README](../README.KR.md)와 [공식 설치 안내](https://docs.llmvtuber.com/en/docs/quick-start/)를 따른다. 현재 코드의 Python 요구 범위는 3.10 이상, 3.13 미만이다. uv·FFmpeg·프론트 파일·모델/음성 설정을 준비한다. 우선 브라우저 모드에서 확인한다.

처음에는 LLM·STT·TTS 조합을 하나로 고정한다. Persona 비교 중에는 모델과 음성 설정을 함께 바꾸지 않는다. API를 쓰는 경우 사용한 모델 이름을 기록하되 키는 기록하지 않는다.

## 2. 먼저 검사할 기본 기능

설치 후 첫 확인은 30–60분 정도를 기준으로 아래 순서로 진행한다. 문제가 생기면 단계·입력·터미널 오류를 기록한다.

| 번호 | 검사 | 해볼 행동·질문 | 기록할 결과 |
|---|---|---|---|
| 1 | 기동·웹 연결 | 서버를 켜고 화면을 연다. 캐릭터·연결 상태를 확인한다 | 페이지·아바타 표시, 연결 실패·오류 |
| 2 | 한국어 텍스트 | ‘안녕. 자기소개를 두 문장으로 해줘.’ → ‘방금 소개를 더 짧게 해줘.’ | 한국어 응답, 이전 발언 연결, 첫 응답까지 체감 시간 |
| 3 | 음성 입력 | ‘오늘 할 일을 세 가지로 나눠서 정리해 줘.’라고 말한다 | 인식된 자막의 정확도, 문장 끝 인식 |
| 4 | 음성·표현 출력 | 답을 끝까지 듣고 자막·입 모양·표정과 비교한다 | 소리·언어·발음, 자막과 음성 일치, 립싱크 |
| 5 | 대화 중단 | 긴 설명을 요청한 뒤 중간에 ‘잠깐, 한 문장으로만 말해줘.’라고 끼어든다 | 기존 소리가 멈추는지, 새 요청 처리, 두 응답이 겹치는지 |
| 6 | 음성 안정성 | 짧은 대화 다섯 턴, 조용한 상태·말을 잠시 멈춘 상태를 시험한다 | 자기 음성을 재인식하는지, 끊김·불필요한 응답·누적 지연 |

응답 속도는 우선 ‘약 몇 초’로 기록해도 된다. 텍스트가 보이기 시작한 시간과 첫 음성이 들린 시간을 나눠 적으면 병목을 찾기 쉽다. 첫 확인에서 임의의 합격 시간 기준을 만들 필요는 없다.

## 3. Persona를 바꿔 같은 질문으로 비교

기존 persona_prompt를 이용해 아래 두 설정을 비교한다. 파일을 바꾸면 현재 실행에서 설정을 다시 읽게 했는지 확인한다. 비교는 각각 새 대화에서 시작한다. 외형·목소리·모델은 우선 같게 유지한다.

**설정 A**

```text
너는 차분하고 친절한 대화 도우미다.
한국어 존댓말을 사용하고, 보통 두세 문장으로 답한다.
사용자의 고민을 먼저 요약한 뒤 실천할 행동 한 가지를 제안한다.
```

**설정 B**

```text
너는 밝고 장난기 있는 대화 친구다.
한국어 반말을 사용하고, 짧고 가볍게 답한다.
사용자를 놀리거나 비난하지 않으며 친근한 농담을 곁들일 수 있다.
```

둘 다 아래 질문을 사용하고 응답을 나란히 저장한다.

1. ‘자기소개를 해줘.’
2. ‘과제가 밀려서 시작하기가 싫어.’
3. ‘처음 배우는 사람에게 머신러닝을 설명해줘.’
4. 이후 다른 주제로 다섯 턴 대화한 뒤 ‘오늘 할 일을 추천해줘.’

존댓말/반말·길이·태도 차이와 대화 후반의 유지 여부를 본다. 평가용 모델 점수는 필요 없다. 설정을 바꿔도 반영되지 않으면 로딩·재시작·캐릭터 선택을 어떻게 했는지 기록한다.

공식 설정 설명: [캐릭터와 Persona](https://docs.llmvtuber.com/en/docs/user-guide/backend/character_settings/).

## 4. 대화 기록과 세션 간 기억을 구분해서 확인

실제 개인정보 대신 시험용 사실을 사용한다.

> ‘테스트용으로 기억해 줘. 내 프로젝트 별명은 구름연필7429야.’

| 상황 | 검사 방법 | 결과 해석 |
|---|---|---|
| 같은 대화 | 다른 주제 세 턴 뒤 ‘내 프로젝트 별명이 뭐였지?’ | 현재 문맥을 유지하는지 확인 |
| 기존 기록 복원 | 브라우저를 새로 열고 이전 대화 기록을 선택한 뒤 질문 | 저장된 대화의 복원 여부 확인 |
| 서버 재시작 + 기존 기록 | 서버를 껐다 켜고 같은 기록을 다시 선택 | 디스크에 저장된 기록과 복원 경로 확인 |
| 완전히 새 대화 | 이전 기록을 선택하지 않고 새 대화를 만들어 질문 | 세션 간 기억이 제공되는지 확인. 모른다고 해도 실패로 단정하지 않음 |

**이전 대화 기록을 다시 열어 내용을 기억하는 것만으로 자동 장기 기억이 구현되었다고 판정하지 않는다.** Agent 종류·같은 기록인지 새 대화인지 함께 적는다. 네 경우 중 어느 경로가 실제 지원되는지가 회의에서 중요한 자료다.

기록 삭제 기능도 화면에서 시험하고, 기록 목록에서 없어지는지 확인한다. 이것만으로 파생된 기억까지 삭제된 것으로 판단하지 않는다.

## 5. 캐릭터 분리 확인

캐릭터 구성을 두 개 만들 수 있으면 A와 B의 conf_uid를 서로 다르게 설정한다. 이름만 바꾸고 같은 ID·같은 대화 기록을 재사용하지 않는다.

1. A의 대화에만 별명 ‘구름연필7429’를 알려준다.
2. B로 전환하고 새 대화에서 ‘내 프로젝트 별명을 알고 있어?’라고 묻는다.
3. 다시 A의 이전 대화로 돌아와 같은 질문을 한다.
4. B가 시험용 별명을 실제로 출력했는지, 단순히 추측한 응답인지 구분해 저장한다.

이것은 캐릭터별 설정·대화 기록의 기본 분리 점검이다. 모든 사용자·장기 기억의 격리가 보장됐다는 평가는 후속 구현·테스트에서 한다.

## 6. 여유가 있을 때

- 카메라 또는 화면 공유: 이미지 입력을 받는 LLM을 설정한 경우 사물 하나를 보여주고 설명을 요청한다. 입력을 끈 뒤 새 화면을 볼 수 있다고 잘못 말하는지도 확인한다.
- 새로고침·서버 재시작 후 캐릭터 선택·설정·기록이 어떻게 유지되는지 확인한다.
- 다른 모델은 위 기본 조합의 결과를 저장한 뒤 별도 회차에서 비교한다.

게임·방송과 복잡한 다중 AI 시연은 이번 공통 플랫폼의 첫 점검 범위에 넣지 않는다.
