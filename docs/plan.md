# 첫 1–2주 계획

## 목표

사용자가 캐릭터의 성격을 설정하고, 해당 캐릭터와 대화하며, 기록과 기억을 이어가는 공통 플랫폼의 구조를 정한다. 게임·방송 연동은 현재 계획에서 제외한다.

## 1주차 — 원본 재현·분석

| 작업 | 산출물 |
|---|---|
| 공통 버전·설정으로 기존 앱 실행 | 두 명 이상이 재현할 수 있는 실행 기록, 성공·실패 항목 |
| 입력부터 응답·음성·아바타까지 코드 추적 | 실제 파일·함수가 연결된 현재 구조도 |
| 캐릭터·연결·세션·기록의 상태 조사 | 관리 주체·저장 위치·수명 표 |
| 기본 기능 범위 합의 | 재사용·수정·추가 기능 목록 |

## 2주차 — 공통 플랫폼 설계

| 영역 | 결정할 내용 |
|---|---|
| Character·Persona | 설정 필드, 성격 의미, 모델 지침 생성·변경 적용 |
| Conversation | 설정·문맥·기억을 이용하는 대화 흐름과 기존 Agent 연결 |
| Memory | 원문·요약·장기 기억 구분, 검색·정정·삭제·정보 격리 |
| Session | 재접속·캐릭터 선택·중단·오류 시 상태 처리 |
| UI·API | 설정·대화·기억 확인 화면과 서버 입출력 |

기존 대화 경로에서 캐릭터 설정 변경이 반영되는 위치를 작게 확인한다. 이 결과를 바탕으로 구조와 계약을 수정한다.

## 역할 배정 초안

A: 실행 환경·전체 구조, B: 캐릭터·Persona, C: 기억·데이터, D: 대화·세션, E: 화면·API. 여섯 명이면 F가 설계 검증과 기록 취합을 맡는다. 실제 담당자와 가용 시간은 첫 회의에서 정한다.

## 종료 기준

- 공통 실행 기록과 기존·목표 구조도.
- 모듈별 책임, 데이터 관계, 입력·출력·오류·중단 계약.
- 설계와 실제 코드 연결점을 확인한 기록.
- 담당자·의존성·완료 조건이 있는 후속 구현 작업.
