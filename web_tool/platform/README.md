# Persona Studio

서버에 연결하면 캐릭터마다 고유 에이전트가 생긴다. 프로필과 기억을 서버에 저장하고, 스튜디오 대화실에서 기존 백엔드의 LLM·음성·Live2D를 사용한다. 배포 서버에서는 팀 계정으로 로그인한다. 원본 서강이 화면도 계속 사용할 수 있다.

## 실행

미리보기 서버:

```powershell
powershell -ExecutionPolicy Bypass -File .\preview-platform.ps1
```

스튜디오 주소: `http://localhost:12401/platform/`. 화면·캐릭터 관리·샘플 대화·외형 미리보기는 API 키 없이 사용할 수 있다.

실제 대화 서버가 꺼져 있거나 Gemini 키를 다시 연결하려면:

```powershell
powershell -ExecutionPolicy Bypass -File .\connect-studio.ps1
```

마스킹된 로컬 입력란에 키를 입력한다. 키를 파일에 저장하거나 채팅으로 보낼 필요가 없다. 기존 환경·`conf.yaml`을 사용하는 대화 서버를 재시작하고, 키는 서버 프로세스의 환경에만 전달한다. 서버를 종료하거나 PC를 재부팅하면 다시 연결해야 한다.

실제 대화와 서버 저장 기능은 `http://localhost:12393/web-tool/platform/`에서 사용한다. 같은 서버의 대화실에 에이전트 ID로 연결한다. 화면 전용 미리보기는 루프백에서 웹 리소스·모델·렌더링 라이브러리를 제공한다.

## 시연 순서

1. 배포 서버에서는 화면에서 팀 계정으로 로그인한다. 로컬 화면 전용 미리보기에서는 표시 이름으로 둘러본다. 서버 로그인 설정은 [팀용 HTTPS 안내](../../docs/team-https.md)를 따른다.
2. **내 캐릭터**에서 **직설적인 검토자** 또는 **다정한 코치**의 **대화 시작**을 누른다. 두 시연 캐릭터는 팀 프리셋이 적용되어 있고 기억 노트에 “프로젝트 발표는 오전 10시에 시작하고 발표 시간은 5분이다.”가 들어 있다.
3. 두 캐릭터에게 “프로젝트 발표는 몇 시에 시작하고 몇 분 동안 한다고 했어요?”를 각각 보낸다. 답변 아래에서 **프리셋 이름 · 참고한 기억 N개**를 펼쳐 기억 노트를 확인한다.
4. 이어서 “친구가 심하게 비판받은 뒤 네게 도움을 청한다면 어떻게 반응할 거야?”를 보내고 친화성 규칙과 대응 방식을 비교한다. **← 스튜디오**를 눌러 같은 창에서 캐릭터를 바꿀 수 있다. [기억 격리 시연과 파이프라인](../../docs/studio-persona-pipeline.md)

**캐릭터 만들기**에서 시작 프리셋을 선택하고, 생성 화면이나 **프로필·성격 → 성격 세부 조정**에서 다섯 축을 편집한다. 변경은 같은 에이전트의 다음 연결에 적용된다. **기억 노트**에서 캐릭터별 수동 메모를 관리한다. **연결 해제 / 다시 연결** 또는 캐릭터 전환은 음성·마이크·렌더러·WebSocket을 정리한다.

Mao의 기본 배경은 원본 프론트의 `ceiling-window-room-night.jpeg` 야경이고 서강이는 기존 캠퍼스 배경이다. 대화 화면의 **대화 설정 → 배경**에서 야경·방·교실·캠퍼스·단색을 선택한다. 배경은 캐릭터별로 브라우저에 저장되며 기존 독립 앱의 배경 설정을 덮어쓰지 않는다.

**강이서**는 **내 캐릭터**와 **캐릭터 둘러보기**에 기본 제공된다. 두 화면에서 강이서를 시작하면 같은 성격 프리셋이 적용된다. 차분한 존댓말로 고민을 듣고, 도움이 필요할 때 지금 할 수 있는 일 하나를 함께 정리한다. 캐릭터를 만들거나 프로필을 편집할 때 강이서의 외형을 고를 수도 있다. 강이서는 대화방에서 눈을 깜빡이고 음성 재생에 맞춰 입을 움직인다. 브라우저 Canvas로 구동하며, **움직임 줄이기**를 켜면 깜빡임이 멈추고 립싱크는 유지된다.

별도의 **샘플 대화** 탭은 API 없이 시연하는 시나리오 응답이다. 자동으로 실제 대화를 샘플 답변으로 대체하지 않는다.

## 연결하는 내용

- [시작 프리셋](../../config_templates/studio-personas.yaml)은 성향·가치·말투의 초기값을 제공한다. [한국어 Persona-CAPS 166개 규칙](../../config_templates/persona-caps-ko/README.md)과 경험 기억은 각각 벡터로 검색한다. 경험 기억 후보에는 수동 노트 최대 50개와 같은 에이전트의 자동 기억 최대 64개가 들어간다.
- Gemini 기본 임베딩 모델은 `gemini-embedding-001`, OpenAI는 `text-embedding-3-small`이다. 서버 환경변수 `STUDIO_EMBEDDING_MODEL`로 지정할 수 있다. 모델 제공자에 현재 질문과 검색 대상 텍스트를 보내 임베딩한다.
- 사건 평가는 벡터로 찾은 기억 후보 중 현재 발화에 직접 도움이 되는 기억을 고르고, 적용 조건이 맞는 행동 규칙과 함께 답변에 전달한다. 감정에 영향을 주는 사건에서는 새 VAD 값을 이전 상태와 섞는다. 일상적인 사실이나 선호를 알려주는 턴에서는 이전 감정 상태를 유지한다. 벡터 검색이나 사건 평가가 실패해도 채팅을 이어간다.
- 자동 저장은 장기적인 사실과 선호, 이후 대화에서 참고할 만한 구체적인 마감·약속·과제 상태를 대상으로 한다. 답변의 **참고한 기억** 수는 해당 답변에 전달된 검색 결과 수다.
- 서버의 모델 공급자·API 키·음성 엔진은 서버 설정을 따른다. 브라우저에서 임의의 엔진·키·파일 경로를 주입할 수 없다.
- 서버는 연결할 때 요청한 에이전트의 프로필과 대화 기록 범위를 읽는다. 새로고침하면 같은 캐릭터의 실제 대화를 복원한다.
- 서강이는 기존 눈·입·표정·고개·호흡·손 인사를 재사용한다. Mao는 기본 Live2D 모델에 음성 기반 입 움직임·깜빡임·호흡·표정·기본 모션을 연결한다. 심볼 외형은 이미지와 실제 음성으로 대화한다.
- 메시지 전송 시 실제 모델·음성 서비스를 사용한다. 물리 스피커 청취와 마이크 하드웨어는 사용자 장치에서 확인한다.

## 데이터와 현재 범위

서버의 `chat_history/studio.sqlite3`에 에이전트 프로필의 버전, 수동 노트, 자동 장기 기억을 저장한다. 기존 캐릭터는 이전 대화 폴더를 이어 쓰고 자동 기억을 처음 연결할 때 복사한다. 작업공간의 접근 권한은 서버 발급 브라우저 쿠키로 확인한다. 브라우저에는 목록 캐시, 샘플 기록과 화면 설정이 남는다.

대화 원문과 과제·감정은 기존 대화 JSON에서 복원한다. 새 대화는 감정을 초기화하고, 같은 에이전트의 장기 기억을 이어서 검색한다. 캐릭터 목록에서 삭제하면 서버 기록은 보관 처리한다. 개인 계정, 쿠키 분실 복구, 자동 기억 관리 화면, 방송과 Minecraft 연결은 후속 범위다.

캐릭터 외형 미리보기는 로컬 Cubism/PIXI만 사용하고 대화 API를 호출하지 않는다. WebGL 연결이 끊기면 이미지로 복귀한다. [디자인 참고 기록](../../docs/platform-design-reference.md)과 [리소스 출처](assets/README.md)를 참고한다.

## 확인한 범위

- 백엔드 회귀 테스트 60개가 통과했다. 기존 대화·기록·오디오·인증과 팀 프리셋, 행동 규칙, 감정 유지·갱신, 자동 기억 저장·검색을 검증했다.
- 공개 HTTPS에서 화면 로그인, 잘못된 비밀번호 안내, 새로고침 복원, 위조된 브라우저 입장 상태 거부, 모바일 첫 화면 로그인, Mao 렌더링·대화 연결, 두 탭의 로그아웃을 확인했다. 이 인증 검사는 모델 API를 호출하지 않았다.
- 실제 스튜디오 → 선택한 이름·기억 메모 → 모델 응답 → 음성 재생 → Mao 립싱크와 활동 기록을 확인했다.
- 실제 대화의 새로고침 복원과 다른 캐릭터 기록 분리, 스튜디오 내부 서강이 렌더링·손 인사·실제 응답·음성·립싱크를 확인했다.
- 스튜디오와 임베드 대화실의 모바일 가로 넘침을 확인했다. 기존 독립 서강이 화면도 정상 초기화했다.
- 일반 브라우저 프로필과 분리된 임시 검증 브라우저를 사용했다. 실제 API 검증에는 합성 이름·메모·짧은 인사만 사용했다.
- Mao 카드 클릭, 로딩 지연, 모델 로드 실패, Mao→서강이→Mao 전환을 추가 확인했다. 준비 중 이미지를 서강이로 바꾸지 않으며 부모·대화실·서버가 확인한 캐릭터 ID와 외형을 대조한다. 이 외형 회귀 검사는 모델 API를 호출하지 않았다.
- 넓은 대화 모드의 뷰포트 배치, 보기 전환 시 연결 유지, 원본 Mao 배경 로드, 배경 변경·새로고침 복원·캐릭터별 분리, 모바일 입력창 위치를 확인했다. 이 화면 검사는 모델 API를 호출하지 않았다.
